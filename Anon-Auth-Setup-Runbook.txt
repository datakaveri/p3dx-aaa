1) Purpose
======================================================================
This document is a reproducible runbook to set up and validate:

- Keycloak (Identity Provider)
- PostgreSQL (Keycloak internal database)
- anon-backend (Node.js/Express Auth API)
- immuDB (immutable audit ledger)
- Optional: React/Vite frontend on a developer laptop

It includes:
- Step-by-step install/run commands
- Environment variables required by the backend
- Test/verification steps
- How to confirm audit events are being stored in immuDB

Security note:
- Do NOT commit or share real secrets (client secrets, admin passwords, .env).
- Replace secrets with placeholders when sharing this document.

======================================================================
2) Architecture (high-level)
======================================================================
Developer laptop (optional)
  - React/Vite frontend (port 5173)
  - Uses HTTP JSON to call backend

Azure VM
  - anon-backend (Node.js/Express) (port 3000)
  - Keycloak (port 8080)
  - PostgreSQL (port 5432, local to VM)
  - immuDB (port 3322, Docker)

Flows
- Register/login:
  Frontend -> anon-backend -> Keycloak Admin API + OIDC Token endpoint

- Audit logging:
  anon-backend -> immuDB

6) PostgreSQL setup (Keycloak internal DB)
======================================================================
Install PostgreSQL
  sudo apt install postgresql postgresql-contrib -y
  sudo systemctl status postgresql

Create database + user for Keycloak
  sudo -u postgres psql

Inside psql:
  CREATE DATABASE keycloak;
  CREATE USER keycloak_admin WITH PASSWORD '<KEYCLOAK_DB_PASSWORD>';
  ALTER DATABASE keycloak OWNER TO keycloak_admin;
  GRANT ALL PRIVILEGES ON DATABASE keycloak TO keycloak_admin;
  \q

Enable password auth (scram-sha-256)
  sudo nano /etc/postgresql/*/main/pg_hba.conf

Ensure entries exist:
  local   all   all                     scram-sha-256
  host    all   all   127.0.0.1/32      scram-sha-256
  host    all   all   ::1/128           scram-sha-256

Restart PostgreSQL
  sudo systemctl restart postgresql

Verify login
  psql -h localhost -U keycloak_admin -d keycloak

7) Keycloak installation & run (26.4.7)
======================================================================
Download & extract
  cd ~
  wget https://github.com/keycloak/keycloak/releases/download/26.4.7/keycloak-26.4.7.tar.gz
  tar -xvzf keycloak-26.4.7.tar.gz
  cd keycloak-26.4.7

Clean Keycloak state (recommended when redoing setup)
  rm -rf data
  rm -rf conf/optimized

Start Keycloak in dev mode using PostgreSQL
  bin/kc.sh start-dev \
    --db=postgres \
    --db-url="jdbc:postgresql://localhost:5432/keycloak" \
    --db-username=keycloak_admin \
    --db-password='<KEYCLOAK_DB_PASSWORD>'

Expected log hints
- Profile dev activated
- Listening on: http://0.0.0.0:8080

9) Keycloak configuration for anon-backend
======================================================================

- Realm used: master (current dev setup)

Client (backend)

Roles
- Realm role: user

10) immuDB setup (audit ledger)
======================================================================
immuDB runs via Docker.

Create volume & run immuDB
  sudo docker volume create immudb-data

  sudo docker run -d \
    --name immudb \
    -p 3322:3322 \
    -v immudb-data:/var/lib/immudb \
    codenotary/immudb:latest

Verify
  sudo docker ps | grep immudb

Create audit database and app user
Approach A (recommended): use repo provisioning script
  cd /home/azureuser/p3dx-aaa
  npm run setup:immudb

Approach B (manual): immuadmin
  sudo docker exec -it immudb immuadmin login immudb
  sudo docker exec -it immudb immuadmin database create anon_audit
  sudo docker exec -it immudb immuadmin user create anon_backend readwrite anon_audit

Backend/app user (example)
- IMMUDB_USER=anon_backend
- IMMUDB_PASSWORD=<IMMUDB_PASSWORD>
- IMMUDB_DATABASE=anon_audit

12) API endpoints
======================================================================
Base URL
  http://<VM_IP>:3000
  or http://localhost:3000 (if running on VM / port-forwarded)

Endpoints
- POST /anon/register
- POST /anon/login
- GET  /anon/me (protected; requires Bearer token + role "user")

Quick curl examples
Register
  curl -X POST http://localhost:3000/anon/register \
    -H "Content-Type: application/json" \
    -d '{
      "username": "user1",
      "email": "user1@example.com",
      "password": "UserPass123!",
      "firstName": "User",
      "lastName": "One"
    }'

Login
  curl -X POST http://localhost:3000/anon/login \
    -H "Content-Type: application/json" \
    -d '{"username":"user1","password":"UserPass123!"}'

Me (replace token)
  curl http://localhost:3000/anon/me \
    -H "Authorization: Bearer <ACCESS_TOKEN>"

14) How to verify audits are being logged (terminal proof)
======================================================================
Option A (simplest)
  cd /home/azureuser/p3dx-aaa
  npm run test:audit

You should see:
- Connected to immuDB
- Selected database
- Found N audit events

Option B (directly query immuDB keys with immuclient)
1) Start immuclient
  docker run --rm -it --network host codenotary/immuclient:latest

2) Inside immuclient:
  login anon_backend -a 127.0.0.1 -p 3322
  use anon_audit
  scan audit:

Expected:
- keys like audit:<uuid>
- audit:type:<event_type>:<uuid>
- audit:subject:<username>:<uuid>
- audit:time:<timestamp>:<uuid>

If you see no events:
- Generate new events by running:
    npm run test:e2e
  then re-run audit verification.

15) Common troubleshooting
======================================================================
A) /anon/register returns 500
- Confirm Keycloak env vars are correct in .env:
  KEYCLOAK_BASE_URL and KEYCLOAK_REALM must be set.
- Confirm Keycloak is reachable from VM:
  curl -I http://localhost:8080/

B) Login returns 401
- Ensure Keycloak client "anon-backend" has Direct Access Grants enabled.
- Ensure KEYCLOAK_CLIENT_SECRET matches client secret in Keycloak.

C) Backend says immuDB is console-only
- Check container:
  docker ps | grep immudb
- Run:
  npm run diagnose:immudb
- Provision if needed:
  npm run setup:immudb

D) No audit events appear
- Ensure IMMUDB_* variables match the created user/db.
- Ensure backend can connect (backend logs show immuDB connected).
- Generate events via test:e2e, then verify.
